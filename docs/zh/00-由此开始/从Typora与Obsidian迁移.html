从 Typora 与 Obsidian 迁移

English: English · 功能对照表 · 欢迎

目标：带着正确预期落地。Inimark 有意 不是二者的完整克隆。

先读诚实对照表 功能对照表，再用下面的清单。

如果你来自 Typora

仍然熟悉的

  • 一块所见即所得书写面 — 不强行左右预览

  • 需要时可用源码模式看原始 Markdown

  • 长稿时的打字机 / 专注舒适感

  • 标题、列表、表格、公式、Mermaid 类图表

你会多得到的

  • 带文件树、快速打开、搜索、书签的 库（文件夹库）

  • [[双链]]、嵌入、出链 / 入链、关系图谱

  • 内置 静态发布，而不只是 Pandoc 导出路径

暂时别指望（尚未对齐）

  • 以 Typora 全套 Pandoc 导出作为主要「发出去」路径

  • 每一项 Typora 偏好都 1:1 对应

迁移步骤

  1. 从 Releases 安装。

  2. 打开文件夹，指向你原本就在写的目录（或先拷一部分到新库）。

  3. 花一天只待在 WYSIWYG — 见 编辑模式。

  4. 开始用 [[ 连接相关笔记 — 见 [[双链与嵌入]]。

  5. 手册差不多了，在文件夹副本上试一次发布。

第一周把链接改写策略保持在 询问，重命名才不会吓到你。

如果你来自 Obsidian

仍然熟悉的

  • 本地文件夹是真相之源

  • [[笔记]]、[[笔记|别名]]、[[笔记#标题]]、![[嵌入]]

  • 图谱 + 入链式列表

  • 任何编辑器都能打开的 Markdown 文件

手感不同的地方

  • 默认是 Typora 式 WYSIWYG，不是「源码 + 实时预览」

  • 没有插件市场、Canvas、Daily Notes、Dataview（见 路线图）

  • 文件树列的是 Markdown 笔记；图片可嵌入解析，但不是树里的一等条目

  • 发布是 本地 SSG，由你自己托管

迁移步骤

  1. 把 Inimark 指向现有库文件夹（或先复制一份更安全）。

  2. 确认 Publish 会自动忽略 .obsidian/ — 产品仍是你的笔记。

  3. 用内置功能重建「插件习惯」：大纲、书签、图谱、保存时格式化。

  4. 暂时用整理好的 MOC 笔记 + 搜索代替 Dataview 式查询。

  5. 重新记几组快捷键 — 完整列表见 查找替换与快捷键。

社区插件和 .obsidian 配置 不会 在 Inimark 里运行。拷贝 Markdown 与资源即可，把插件状态留在身后。

切换前的文件夹与链接卫生

检查为什么
标题尽量唯一[[双链]] 解析更干净
图片路径优先相对路径搬家和发布都更稳
别依赖块引用 ^id还不是完整体系
先备份 / git 提交重命名 + 改写很强大

习惯对照

旧软件里的习惯在 Inimark
左右分栏预览待在 WYSIWYG；需要时才看源码
命令面板插件快速打开 + 设置搜索 + 快捷键
图谱视图侧栏 / 浮动 关系图谱
发布 / 导出设置 → 发布，或 pnpm docs:build
主题主题包（.inimark-theme.json）

迁完之后

  • 走一遍 日常场景 里的场景配方

  • 觉得「缺了什么」时扫一眼 常见问题

  • 诚实缺口记在 路线图
